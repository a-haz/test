FAQ

How are these passwords generated?

With crypto.getRandomValues(), the browser's cryptographically secure random number generator — the same class of randomness used for encryption keys. Rejection sampling is used so every character in the pool is exactly equally likely (a plain Math.random() or naive modulo would introduce bias).

Can anyone see the passwords I generate?

No. This is a static page with no backend, no analytics and no network requests after load. Generated passwords exist only in your browser's memory and are gone when you leave the page.

How long should a password be?

For anything important, 16+ characters with all character sets enabled — that's roughly 100+ bits of entropy, far beyond brute-force range. The real best practice: use a password manager so every account gets a unique random password, and enable two-factor authentication where offered.

What does the strength meter measure?

Entropy in bits: length × log₂(pool size). 60+ bits is reasonable, 80+ is strong, 100+ is excellent. It assumes a truly random password — human-invented passwords are far weaker than their length suggests.
